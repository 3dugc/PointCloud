# 持续定位量化模拟

在 Unity 中打开 `PointCloudSimulation.unity`，点击 Play。菜单入口是 **Tools → Point Cloud → 打开独立模拟场景**。建议 Game 窗口用 16:10 / 16:9，开启 Maximize On Play。

## 先做一个能看懂的对照

1. 选择“误差对照”和对应设备参数，使用“手动阶跃（可重复）”，点击开始。
2. 等首次定位完成。默认准备注入 **8 cm 平移 + 3° 偏航**；也可以把其中一项调为0，单独测试平移或旋转。
3. 点击“注入漂移”。这一刻两组都应出现同样的物理误差。橙色组保留首次位姿，青色组继续使用正式定位维护逻辑。
4. 保持1倍速度，看青色误差曲线逐步下降、橙色误差保持。普通维护共需3个一致结果；第1、2个结果已经开始有上限的预矫正，第3个结果完成确认。iOS约每0.75秒采样、最终平滑0.75秒；Rokid约每1秒采样、最终平滑1秒。首次定位和跟踪恢复仍使用5次严格确认。
5. 达到稳定后再次注入，检查第二次、第三次矫正。注入100 cm或较大旋转则会触发严格重定位，不能期待直接平滑跳过去。
6. 可以暂停读数；停止后保留实验结果。切换场景/参数后要重新开始。

右侧显示位置误差（cm）、角度误差（°）、曲线内实际采样点的位置误差均方根（RMS），以及本次扰动达到稳定恢复所用的模拟时间。恢复参考条件是：扰动停止后，已验证跟踪、位置误差≤1 cm且角度误差≤0.5°，连续保持2秒。参考线只用于实验评价，不改变生产门禁。RMS包含等待、跟踪失效和平滑过程，不只挑最后一帧。它按采样点等权计算；最多1200点、最高10 Hz，不是时间加权均值。快放或卡帧可改变采样间隔，数值对比以固定步长自动检查为准。

俯视图中的白色十字是固定物理真值，青色是开启矫正后的内容位置，橙色是关闭持续矫正的对照，黄色是合成测量，长条表示朝向。场景自动缩放便于看清厘米级偏差，数值本身不放大。曲线保存有界的最近采样历史。

## 其余量化场景

- **持续漂移30秒**：每秒注入0.2 cm平移和0.05°偏航，30秒后停止。应观察到多次维护修正，停止漂移后误差继续收敛。
- **持续漂移＋噪声**：再加入确定性的毫米级、0.1°以内测量噪声。观察残余误差和整段RMS，不能要求每一帧都为零。
- **短暂错误匹配**：短时注入高质量但错误的1 m候选。应由门禁挡住，不能把真实位置正确的物体移错。
- **持续错误匹配**：持续一致的错误候选可能经严格重定位被接受。此时青色误差会变大、橙色仍正确；自动检查明确输出 `LIMITATION`，不把“成功回调”当作定位准确。

“运行双端自动检查”覆盖量化场景以及原有流程案例，完整结果在 Console。测试还覆盖最终确认前已经发生预矫正、连续两次注入、平滑中间位姿、非零旋转/平移的坐标变换、观察与被测输出独立、跟踪丢失及停止后的统计冻结。

## 为什么这次能测误差

实验固定物理世界真值，并单独维护“物理世界→追踪坐标”的漂移变换T。合成定位候选来自T、固定真值和确定性噪声，经过正式 `ImmersalMaintenanceState` / `LocalizationConfirmationGate`，再把输出用T的逆变换换回物理世界计算误差。关闭矫正的对照保留第一次输出，用同一个T的逆变换换算，因此两组承受相同漂移。

真值只用于生成合成观察和独立评分，不作为门禁放行条件。量化相机轨迹、签名、噪声和错配按实验时钟确定，不依据矫正输出或重定位状态自动生成有利输入。实验在共同首次定位后建立对照，评价的是维护阶段，不包含首次识别性能。

本实验不运行Immersal原生图像识别，也不模拟所有真实传感器误差；不能据此宣称真机地图识别率、漂移分布或资源释放已验收。另有实际后端循环集成测试，承担异步扫描和取消清理验证。

## 原有流程案例

切换到“原有流程案例”仍能运行下面的检查。这里白色十字只表示零点参考，8 cm / 1 m候选变化演示不再标作真实纠偏目标。

正常观察应完成首次定位并进入低频维护。
失败、空白画面、固定重复视角，以及不移动的低头转动不应完成放置。
25 分匹配在当前 Rokid 参数下可以通过，iOS 参数下不能通过。
放置后 2 毫米抖动应被忽略；8 厘米偏移应缓慢修正；1 米突跳先拒绝直接修正。
持续的大偏差或旧验证到期会切换到首次定位门禁，重新取得不同视角的合格证据后，
才允许接受 1 米的新位置。永久拒绝所有大偏差不再视为测试通过。
维护案例使用固定视角和相同图像签名，验证静止时的新采样也能确认修正。
“转头移动中短暂匹配失败”先积累两个结果，中途移动并连续失配，
有效期内应保留两个结果，但不能在失配期间自动放置；恢复有效匹配后才完成。
真实跟踪丢失仍清空累计，不等同于普通的单次地图匹配失败。
“稳定的错误结果”刻意提供足够视角和高分，会通过门禁并偏离白色正确位置。
这项输出标为 LIMITATION，说明仅凭稳定结果不能证明房间正确。

本场景只在 Unity 编辑器内运行，不加入正式构建场景列表。
它不加载业务场景，不需要设备、账号、地图 ZIP 或 Immersal Runtime。
模拟后端使用 simulation 类型，不会接管正式的 immersal 地图。

模拟器直接驱动正式 ImmersalMaintenanceState，共享门禁切换、验证到期、
大偏差升级、平滑和采样间隔。SimulationModel 只生成输入、推进时钟与显示决定，
不再独自实现另一套维护流程。匹配质量与上下文朝向使用 ImmersalPosePolicy，
确认使用 LocalizationConfirmationGate，取消/替换经过 PointCloudLocalizer.TrackAsync。
空白画面测试调用正式 FrameEvidenceAnalyzer。其他输入是人工生成的相机姿态、
图像签名和匹配结果，不是相机照片，也没有运行 Immersal 原生识别。
时钟、跟踪丢失和原点重置信号由模拟器注入；不能以此证明真实后端异步时序、SDK 清理、
相机独占、平面识别、图片识别、联机或真实地图识别已经通过。

本工程对应设备直接引用 Assets/Platform/PointCloud 的正式参数资产。
另一个设备的参数放在 Profiles，是另一工程正式参数的快照（2026-09-08）。
另一端调参后需要同步快照；场景运行时不改写任何参数。
本独立 Rokid 示例保留同样的路径：Rokid 使用 Assets/Platform/PointCloud/RokidLocalizationProfile.asset，iOS 使用 Assets/PointCloudSimulation/Profiles/iOSLocalizationProfile.asset。场景序列化引用和自动检查加载路径均指向这两份资产。

双端自动检查还覆盖共享维护状态的四条路径：恢复后静止重复输入不能通过首次门禁；
候选相差 6 厘米时能完成严格恢复；长期没有合格新结果时验证到期；
平滑期间原点重置立即中断旧修正，重新确认之前不再发布位置。
Tests 同时覆盖独立场景 Play 模式下的首次回调、连续替换与取消后不再更新。
测试不是识别准确率评估，也没有用模拟器的成功代替真实后端的集成检查。
